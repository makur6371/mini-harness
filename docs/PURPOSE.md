# mini-harness 项目章程

> 本文档是范围的标尺。任何改动/提议先回这里对照;不服务下面两条约束的,默认不合并。

## 目的

做一个**最小可行 Agent harness,专供垂直行业网站接入**(咨询型 / 办事型)。
任何网站用一行代码挂上、用一个插件包文件完成垂直化,内核不动。
借鉴 DeepSeek Harness 的"万能插件"思想,但砍掉它的完整大架构。

## 两条硬约束(优先级最高)

1. **极容易装进各自垂直网页** —— 一行 `<script>`,Shadow DOM 不污染宿主页,跨域能跑。
2. **极容易垂直化** —— 一个 `sites/xxx.site.mjs` 决定身份 / 守门 / 工具白名单 / 呈现,内核零改。

凡两条之外的能力,默认不做。

## 非目标(明确不做)

- ❌ 不复刻 DeepSeek Harness 全功能(那是开发者自用的大 harness)
- ❌ 不做多租户 SaaS / 后台控制台 / 计费 / 用户系统
- ❌ 不当面向公众开发者的通用 Agent 框架(不是 LangChain 竞品)
- ❌ 不内置 RAG / 向量库 —— 检索是站点包自己接,那是"垂直内容"不是 harness 职责
- ❌ 不给访客暴露通用工具(bash 等);工具白名单由站点包决定
- ❌ 不堆前端花活 —— 打字机流式够用即止

## 设计原则(卡住自己别乱加)

- **内核冻结**:`kernel.mjs` 133 行 / 5 缝,不随功能膨胀。新能力先问"能不能做成插件"。
- **一切是缝上的插件;插件之间零依赖。**
- **垂直化的单位是"站点包文件"**,不是配置开关、不是 fork。
- **零运行时依赖**,保持小、好审计、好嵌入(浏览器测试等纯测试期依赖除外)。
- **安全靠纵深**(token + 限流 + Origin),不靠单一密钥。

## 决策三问(每个提议先过)

1. 它服务"易嵌入"或"易垂直"吗?两个都不沾 → **不做**
2. 能做成插件 / 站点包、不动内核吗?不能才考虑动内核
3. 是某具体场景才需要的吗?是 → 进站点包示例,不进核心

## 现状(v0.3.0)

已具备:内核(冻结)、双形态(CLI 调试 / 网站嵌入)、流式打字机、CORS、token 鉴权、
令牌桶限流、会话持久化与重启恢复、两个站点包示例(诊所 / 电商)、部署包。
代码侧"能上公网"已齐;`test.mjs` + `test-web.mjs` + `test-stream.mjs`(LLM 协议保真) + `test-browser.mjs`(真 Chrome)全绿。
